# SETUP.md — PyuHeritage (pyu_heritage) Developer Setup

This guide explains how to set up and run the PyuHeritage web application from scratch on a new machine.

## Project overview

- **Backend:** Node.js (Express 5) + EJS templates
- **Database:** MySQL 8 (database name `pyu`)
- **AI chat (`/chat`):** Retrieval-Augmented Generation (RAG)
  - Question embeddings are computed locally with the Hugging Face model `Xenova/all-MiniLM-L6-v2` (downloaded on first run, ~90 MB).
  - Answers are generated by an LLM via the **OpenRouter API** (requires an API key).
  - Context is retrieved from indexed PDF documents (`node/rag/documents/`) and artifact records stored in MySQL.
- **File uploads:** artifact images (jpg/png/webp/gif, max 5 MB) and 3D artifacts (image + `.glb` model, max 100 MB).

---

## Prerequisites

Install the following before continuing:

| Requirement | Version / Notes |
|---|---|
| Node.js | v20 LTS or newer (needed by Express 5 and `@huggingface/transformers`) |
| MySQL | 8.x, running locally on port 3306 |
| Git | Any recent version |
| Internet access | Required on first start (downloads the embedding model) and for chat (OpenRouter API) |

> If you use Windows, MySQL Workbench or phpMyAdmin (via XAMPP) can be used instead of the `mysql` CLI. Steps below show both options.

---

## Step 1 — Clone the repository

```bash
git clone <repository-url> Project_v1.0
cd Project_v1.0
```

The whole application lives inside the `node/` folder.

---

## Step 2 — Set up the MySQL database

Create the `pyu` database and its tables by running the SQL scripts in `node/database/`. Order does not matter (all three create the database if it does not exist).

1. `artifacts.sql` — table `artifacts`
2. `three_d_artifacts.sql` — table `three_d_artifacts`
3. `artifact_embeddings.sql` — table `artifact_embeddings`

### Option A — MySQL CLI

Open a terminal in `node/database/` and run:

```bash
mysql -u root -p < artifacts.sql
mysql -u root -p < three_d_artifacts.sql
mysql -u root -p < artifact_embeddings.sql
```

### Option B — MySQL Workbench / phpMyAdmin

Open each `.sql` file and run the whole script as a query, or import the file.

> **Note:** The scripts only create the schema — they insert **no sample data**. To add artifacts, use the admin JSON API (e.g. `POST /admin/artifacts`, see Routes below) or insert rows manually. When you add artifacts, the chat's artifact embeddings are created automatically.

---

## Step 3 — Create the `.env` file

The repository ships a template at `node/.env.example`. Copy it and fill in your local values:

```bash
cd node
copy .env.example .env    # Windows
# or on Linux/Mac:  cp .env.example .env
```

### Environment variables

| Variable | Description | Example |
|---|---|---|
| `PORT` | Port the web server listens on | `3003` |
| `DB_USER` | MySQL username | `root` |
| `DB_PASSWORD` | MySQL password | `your_mysql_password` |
| `DB_HOST` | MySQL host | `localhost` |
| `DB_PORT` | MySQL port | `3306` |
| `DB_NAME` | Database name | `pyu` |
| `OPENROUTER_API_KEY` | OpenRouter API key for AI chat — get one at https://openrouter.ai | `sk-or-v1-...` |
| `OPENROUTER_MODEL` | LLM model used for chat answers | `deepseek/deepseek-v4-flash` |
| `OPENROUTER_SITE_URL` | Site URL reported to OpenRouter | `http://localhost:3003` |
| `OPENROUTER_SITE_NAME` | Site name reported to OpenRouter | `PyuHeritage` |

> **Important:** `.env` is gitignored and never shared. The OpenRouter API key is a secret — pass it to other developers privately, not through the repository. Without a valid key, the chat page still loads but returns *"OpenRouter API key not configured"*.

---

## Step 4 — Install dependencies

From the `node/` folder:

```bash
npm install
```

This installs the project dependencies from `package.json` (Express, EJS, mysql2, multer, axios, `@huggingface/transformers`, pdf-parse, etc.).

---

## Step 5 — (Optional) Backfill embeddings for existing artifacts

The chat's artifact search relies on a row in `artifact_embeddings` for every artifact in `artifacts` and `three_d_artifacts`. Rows are added automatically whenever you create or update an artifact through the admin API.

**Only** if your database already contains artifacts (e.g. you imported a database dump) and the embeddings table is empty, run the backfill script:

```bash
node rag/seedEmbeddings.js
```

---

## Step 6 — Start the server

From the `node/` folder:

```bash
npm start
```

Expected output on first start:

```
Database Connected
Server listen at port: 3003
Indexing <n> chunks...
...
PDF RAG ready: <n> chunks indexed
Artifact RAG ready: <n> items loaded from DB
```

> **First start is slow (a few minutes):** embeddings for all PDFs in `node/rag/documents/` are computed and cached in `node/rag/cache.json`. On later starts the cache is loaded instantly. The embedding model is also downloaded once.

## Step 7 — Verify it works

Open the following in your browser:

| URL | Page |
|---|---|
| `http://localhost:3003/` | Home page |
| `http://localhost:3003/chat` | AI "Pyu Assistant" chat (needs OpenRouter key) |
| `http://localhost:3003/history/cities` | Pyu ancient cities |
| `http://localhost:3003/history/artifacts` | Archaeological artifacts |
| `http://localhost:3003/history/artifacts/3d` | 3D artifacts |
| `http://localhost:3003/admin/dashboard` | Admin dashboard |

### Admin API routes

| Method | Route | Action |
|---|---|---|
| GET | `/admin/artifacts` | List artifacts |
| POST | `/admin/artifacts` | Create artifact (multipart: `title`, `description`, `category`, `image`) |
| POST | `/admin/artifacts/:id` | Update artifact |
| DELETE | `/admin/artifacts/:id` | Delete artifact |
| GET | `/admin/3d-artifacts` | List 3D artifacts |
| POST | `/admin/3d-artifacts` | Create 3D artifact (multipart: `title`, `description`, `category`, `image`, `model` `.glb`, optional `voice` audio) |
| POST | `/admin/3d-artifacts/:id` | Update 3D artifact |
| DELETE | `/admin/3d-artifacts/:id` | Delete 3D artifact |

## Troubleshooting

| Symptom | Likely cause / Fix |
|---|---|
| `Database connection error` | MySQL not running, or wrong `DB_USER` / `DB_PASSWORD` / `DB_HOST` in `.env`. Check MySQL is running and the credentials match. |
| `Error: listen EADDRINUSE` | Port `3003` is already used. Change `PORT` in `.env` (and update `OPENROUTER_SITE_URL` to match). |
| `No PDF files found in rag/documents/` | The `node/rag/documents/` folder is missing its PDF files. The chat still works using only the artifact database. |
| Chat says `OpenRouter API key not configured` | `OPENROUTER_API_KEY` is missing or set to the placeholder `sk-or-v1-YourKeyHere`. Enter a valid key in `.env` and restart. |
| First start takes very long | Expected — PDFs are being embedded and cached. Subsequent starts are fast. |
| Uploads rejected | Images must be jpg/png/webp/gif (max 5 MB); 3D models must be `.glb` (max 100 MB). |
